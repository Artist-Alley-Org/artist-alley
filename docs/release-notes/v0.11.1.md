## Artist Alley v0.11.1: Test runs we can reproduce

v0.11.1 strengthens the checks behind Artist Alley. The app's everyday workflow is largely unchanged, but its tests now start from public, versioned sample libraries and run on GitHub-hosted machines. That gives contributors the same starting point when a test fails and makes the project's release checks less dependent on its own infrastructure.

### The same sample data on every run

The dataset-based browser checks now use fixed editions of the `site_a` and `site_b` sample libraries. Each run pins the edition and checks its files before seeding, so a failure can be repeated against the same data. A daily full-corpus check also walks every post and asset, looking for paging mistakes that a smaller test library could miss.

These dataset editions were published as provisional prereleases, accepted by the project owner; publishing them is not a per-file rights clearance. The demo seed and its Kaggle dataset have not changed in this release.

### Checks run on GitHub-hosted machines

Browser tests, integration checks, image builds, and the release workflow now run on GitHub-hosted runners. Contributors can now reproduce the dataset-based checks from public data, without access to the project's private archive.

### Security and clearer licensing

Updated web dependencies resolve fourteen reported advisories, including one critical advisory. The admin License page now describes community mode accurately: it has no seat or asset cap, while LDAP, SAML, and multi-tenant deployments remain license-gated. Release image metadata and announcements also describe the license and published tags accurately.
