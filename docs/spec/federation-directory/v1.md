# artist-alley federation directory — wire format v1

**Status:** v1 (Phase 1.22.B-c).
**Stability:** the wire format is open and stable. Anyone may run
a directory implementation; instances may subscribe to multiple
directories simultaneously.

## What this spec is

A federation directory is a public, opt-in **discovery aid** that
lets an artist-alley instance find peers it might want to pair
with. It is **not** a trust mechanism. Listed instances are
candidates for pairing; the actual trust relationship is
established by the per-peer handshake in
[federation/v1.md §11](../federation/v1.md). The directory just
saves operators from emailing URLs to each other.

This spec describes:

- The **HTTP API** a directory server exposes.
- The **DNS-TXT verification** an instance must complete to be
  listed (mandatory — no self-declared listings).
- The **subscriber polling** + **local caching** behaviour an
  artist-alley instance follows when subscribed to a directory.

## What this spec is NOT

- Not a trust statement. A listed instance is one a directory
  operator believes claims its name correctly. Pairing is still
  a per-operator decision.
- Not a registry of identities. The same `instance_url` can be
  listed in multiple directories with different display names.
- Not a moderation tool. Directories may de-list instances; that
  doesn't affect peers who already paired.
- Not federation-protocol-bearing. Directories carry no
  activities, no posts, no DMs. They are static lists.

## Why open spec, multi-directory, mandatory DNS-TXT

We hosted **one** directory at `artist-alley.org` for
convenience. We made the protocol **open** so we never become a
chokepoint — anyone can run their own. We made multi-subscription
**first-class** so a studio can subscribe to a hosted directory
AND their own internal one. We made DNS-TXT **mandatory** so a
listing is at least proof-of-domain — without it the directory
is a phishing surface.

DHT (Kademlia-style fully-decentralised discovery) was considered
and rejected: moderation is materially harder, spam resistance
requires proof-of-work / proof-of-stake we don't want, and a
directory model lets us cleanly ship the DNS-TXT identity layer.
Hosted-directory operators carry the moderation burden; if you
don't trust any of them, run your own.

## HTTP API

All endpoints are HTTPS-only. JSON request + response bodies.

### `GET /v1/listing`

Returns the directory's full set of verified entries. Bounded
result; use `?cursor=<opaque>` to page.

**Query parameters:**

| Name     | Type   | Default | Description |
|----------|--------|---------|-------------|
| `limit`  | int    | 100     | 1..500 |
| `cursor` | string | empty   | opaque cursor from prior response |

**Response 200:**

```json
{
  "directory": {
    "name": "artist-alley.org public directory",
    "operator_url": "https://artist-alley.org",
    "spec_version": "aa-directory/v1",
    "generated_at": "2026-06-05T12:00:00Z",
    "signature": "<base64 Ed25519 sig over the canonical entries[] payload>",
    "public_key_pem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
  },
  "entries": [
    {
      "instance_url": "https://studio-a.example",
      "display_name": "Studio A",
      "instance_public_key_pem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----",
      "fingerprint": "ab12cd34...",
      "region": "us-west",
      "description": "Cooperative game studio. Public site for fan art submissions.",
      "tags": ["games", "art", "indie"],
      "verified_at": "2026-06-04T11:00:00Z",
      "verified_via": "dns-txt",
      "listing_id": "01HK..."
    }
  ],
  "next_cursor": null
}
```

**Signature:** the directory operator's Ed25519 signs the RFC-8785
canonical encoding of the `entries` array (NOT the whole envelope
— subscribers compute over `entries` so the wrapper is allowed to
carry mutable metadata like `generated_at`). Subscribers MUST
verify the signature before trusting the entries. The operator's
public key is published at `GET /v1/operator` for first-fetch
trust-on-first-use; subscribers cache it.

### `GET /v1/operator`

Returns the directory operator's own identity. Subscribers fetch
this once when first adding a directory subscription, cache the
public key, and use it to verify `/v1/listing` responses on every
subsequent poll. Key rotation requires re-subscription.

**Response 200:**

```json
{
  "name": "artist-alley.org public directory",
  "operator_url": "https://artist-alley.org",
  "contact": "directory@artist-alley.org",
  "spec_version": "aa-directory/v1",
  "public_key_pem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----",
  "fingerprint": "ab12cd34..."
}
```

### `POST /v1/register`

An instance applies for listing. The request includes a DNS-TXT
proof token that the directory will verify against the claimed
`instance_url`'s domain BEFORE adding the listing.

**Request body:**

```json
{
  "instance_url": "https://studio-a.example",
  "display_name": "Studio A",
  "instance_public_key_pem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----",
  "region": "us-west",
  "description": "Cooperative game studio.",
  "tags": ["games", "art", "indie"],
  "dns_txt_token": "<the token from POST /v1/challenge>"
}
```

**Response 201:** new listing created (DNS-TXT verified).
**Response 202:** DNS-TXT not yet propagated; retry later.
**Response 400:** malformed.
**Response 401:** token unknown / expired.
**Response 403:** DNS-TXT lookup failed; not listed.

### `POST /v1/challenge`

Generate a DNS-TXT challenge token. Returns the token + the
exact DNS-TXT record content the instance must publish at
`_artist-alley.<host> TXT`.

**Request body:**

```json
{ "instance_url": "https://studio-a.example" }
```

**Response 200:**

```json
{
  "token": "ed7c91...",
  "record_name": "_artist-alley.studio-a.example",
  "record_value": "v=aa1; directory=artist-alley.org; token=ed7c91...",
  "expires_at": "2026-06-05T13:00:00Z"
}
```

Tokens expire 1 hour after issue. The instance publishes the
TXT record, then calls `/v1/register` with the same token.

### `DELETE /v1/listings/{instance_url}` (operator-only)

Remove a listing. Authenticated via a bearer token only the
directory operator holds. Listed instances de-list themselves by
removing the DNS-TXT record + waiting for the directory's
re-verification cycle (default: every 7 days; configurable).

## DNS-TXT verification

The mandatory bar for inclusion. An instance proves it controls
the domain in its `instance_url` by publishing a TXT record
under a well-known subdomain.

### Record format

**Name:** `_artist-alley.<host>`
- For `https://studio-a.example` → `_artist-alley.studio-a.example`
- For `https://art.studio-a.example` → `_artist-alley.art.studio-a.example`

**Value (single string per record):**
```
v=aa1; directory=<directory operator host>; token=<challenge token>
```

- `v=aa1` — version (required, must be `aa1` for this spec)
- `directory=<host>` — bare hostname of the directory operator
  (e.g., `artist-alley.org`). MUST match the operator the
  instance is registering with — defends against a malicious
  directory replaying a token to a different one.
- `token=<hex>` — the token returned by `/v1/challenge`

**Multiple records** under the same name are allowed (one per
directory the instance publishes to). The directory verifier
scans all TXT records under the name; the first matching one
wins.

### Verification steps (directory server)

1. Receive `POST /v1/register` with `instance_url` + `dns_txt_token`.
2. Look up the host part of `instance_url`.
3. Resolve `_artist-alley.<host>` TXT (UDP first, TCP fallback).
4. Iterate records:
   - Parse `v=`, `directory=`, `token=`.
   - Require `v=aa1`.
   - Require `directory=<our operator host>`.
   - Require `token=<the supplied token>`.
5. First matching record → verified. No matching record → 403.
6. Persist `verified_at = NOW()`, `verified_via = "dns-txt"`.

### Re-verification

Default: every 7 days. Listings whose DNS-TXT no longer resolves
are flagged `unverified` (NOT immediately removed — DNS hiccups
shouldn't drop legitimate listings). After 2 consecutive failed
re-checks (14 days default) the listing is de-listed.

Operators MAY configure tighter cycles; subscribers see a
`verified_at` timestamp per entry and can ignore stale ones.

## Subscriber behaviour

### Subscribing to a directory

1. Admin enters `directory_url` (e.g., `https://artist-alley.org`).
2. Subscriber fetches `GET /v1/operator`, caches the operator
   pubkey + fingerprint.
3. Admin reviews the operator fingerprint (UI shows it) and
   confirms — this is the trust-on-first-use step.
4. Subscriber starts polling.

### Polling cadence

Default: every 6 hours. Polls happen lazy-on-first-read +
background refresh. Subscribers MUST honour `Cache-Control: max-age`
headers when present.

### Local caching

Subscribers MUST cache the last successful poll's entries
locally. If a poll fails (directory unreachable, signature
invalid, etc.), the cached entries remain usable + the
subscriber surfaces "directory not reachable since X" in the
admin UI. Cached entries don't expire on their own — they
persist until the next successful poll overwrites them or the
admin unsubscribes.

### Signature verification

Every poll response is signature-verified against the cached
operator pubkey. Verification failures DROP the entire poll —
no entries are updated. If the directory operator rotated keys
(rare; not v1), the admin must re-subscribe.

### Per-entry verification on display

When the admin clicks "Pair" on a directory entry, the
subscriber MUST:

1. Show the entry's `fingerprint` + `verified_at` + `verified_via`.
2. Allow the admin to verify the fingerprint out-of-band before
   proceeding.
3. Pre-populate the existing handshake `/initiate` flow with
   `instance_url` + `display_name`.
4. The handshake protocol (v1.md §11) handles the actual
   pairing; the directory is purely advisory.

The subscriber MUST NOT auto-pair from directory entries.
Discovery and trust are deliberately separate.

## Privacy considerations

- Directory listings are **public**. Don't list an instance you
  don't want indexed.
- The DNS-TXT record is **public** (DNS is public). Anyone can
  see which directories an instance has registered with.
- `region`, `description`, `tags` are operator-supplied + public.
  Don't put sensitive info in them.
- The directory operator sees: every registration attempt + every
  poll. Operators MAY publish access logs; subscribers SHOULD
  consider the privacy implications of subscribing.

## Versioning

The version string is `aa-directory/v1`. Future protocols (`v2`,
etc.) introduce breaking wire-format changes; the `spec_version`
field on `/v1/operator` lets subscribers detect mismatch and
refuse to poll.

Backwards-compatible additions (new optional fields) don't bump
the version. Subscribers MUST ignore unknown fields.
