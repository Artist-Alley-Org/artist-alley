## Governing decisions and open conflicts

1. ADR 0058 reserves public distribution for Layer A and explicitly keeps
   `site_b` private. The owner has chosen to replace `site_b` with a public
   corpus. Amend the ADR before publishing the replacement. Keep the current
   Layer B bytes private throughout selection, validation, and cutover; retain
   the old private corpus only in private storage under a distinct identity.
2. ADR 0080 makes `site_a` CI coverage class-based. The declared
   `requiredDims` in `app/internal/seed/coverage.go` includes media,
   companions, relations, mature assets, and public posts. The fixture
   contract must trace each required class and each consumer test to a
   specific input and assertion. A peer floor is needed if a test begins
   reading `site_b`'s seeded content.
3. ADRs 0097 and 0098 distinguish committed profile content, produced
   bytes, and preserved archive bytes. A release can be byte-reproducible
   from an attested snapshot even where original `local` inputs cannot be
   regenerated. Its manifest must state which evidence kind applies.
4. `RELEASING.md` currently describes Kaggle publication when a release
   republishes the seed. The owner chose metadata-only public dataset
   repositories under Artist-Alley-Org with versioned GitHub Release
   archives for CI (see "Distribution shortlist"). That decision must still
   be reconciled with this release procedure before CI changes are treated
   as complete.

## Distribution shortlist (decided 2026-11-11)

**Decision (owner, 2026-11-11):** both public dataset repositories
(`site_a` and `site_b`) belong under Artist-Alley-Org and hold metadata and
tooling only. Dataset binary bytes are published as versioned,
checksum-verified GitHub Release archives for CI. There is no public Git or

below is kept as the evidence the decision was made against.

**ADR 0100 (proposed)** records this transport:

before publication and cutover. Status: two LOCAL candidate archives are
retained privately, the post-exclusion `site_a` candidate and the `site_b`
candidate. No candidate is a release pin or authorizes an upload. No CI job
downloads a payload yet.

## Draft duplicate-fixture contract

The current upload path checks for an existing live asset by
`(owner_user_ref, file_hash)`. The database's partial unique index enforces
that same pair under concurrent uploads, even when the pre-check misses;
per-team and global application checks are not implemented. The fixture
contract should record at least these byte-verified cases, with explicit
expected asset IDs and API outcomes for the configured dedup behavior:

| Case | Expected identity relationship |
| --- | --- |
| Identical bytes, different filenames, same owner | One live asset identity; the second upload takes the dedup path. |
| Identical bytes, different proposed metadata, same owner | One live asset identity; do not promise an automatic metadata merge. |
| Identical bytes, different owners | Two legal asset identities. |
| Different bytes that look alike | Two asset identities. |
| Identical bytes on separate federation peers | Separate peer-local identities; no cross-peer dedup promise. |

Companion-file and near-duplicate behavior must be checked against their
handlers before they receive an expected outcome. The release manifest
will name every intentional case and the hashes that make it a fixture;
unmarked duplicates are not silently treated as test data.

contain at least two different byte-identical assets across peers. The

carry over the private `site_b` manifest or its asset IDs. Two `site_a`

### Overlap contract and validator

The two anchors are now declared in

`app/internal/seed/overlap.go`, run as:

```sh

```

to select it. For each peer it should name the archive part names, byte

## Rights ledger tool

`aa seed-rights` (`app/internal/seed/rights.go`) gives every file in a
selection report exactly one ledger row. It is offline, has no default
paths, and prints only to stdout, so the caller decides where a private
ledger lives:

```sh
aa seed-rights --selection <report> --draft > <private ledger>
aa seed-rights --selection <report> --ledger <private ledger> --check
```

The ledger schema is `artist-alley.rights-ledger/v1`. Its `selection`
header binds the SHA-256 of the raw report bytes, the report schema,
profile, coverage depth, file count and unique bytes. Each entry pins one
closure path, its byte length, SHA-256 and `primary_for` / `companion_of`
roles as the report gives them, so companions, shared companions and paths
with both roles keep their own rows. The reviewer fills in `status` and
`review`. Status is `pending` (the draft value), `hold` (do not package;
replace or remove), or `reviewed_allow`. A `reviewed_allow` row must carry
a `review` with at least one source reference, a license or terms
identifier, at least one license-evidence reference, `redistribution:
"allowed"`, an attribution record whose `required` is stated either way
(with text or a notice when required), a reviewer and a `YYYY-MM-DD` date.
Any other status is refused.

`--draft` refuses a malformed or internally inconsistent report: unsafe,
unsorted or duplicate paths, roles that the asset rows do not back, files
an asset needs but the report omits, or counts that disagree with the
lists. `--check` refuses a ledger bound to a different report, missing,
extra, duplicate or unsorted entries, changed bytes, hashes or roles, an
unknown status, or an incomplete `reviewed_allow` review. It exits non-zero
unless there is at least one entry, every entry is `reviewed_allow`, and the
report has no `unknown_model_format` assets.

The listed files are the complete package closure only when
`counts.unknown_model_assets` is 0. For a model in a format whose
references format3d cannot read, the report may be missing files that model
needs, so reviewing every listed row cannot cover them. Such a report still
drafts as a worklist, but `--check` is never eligible for it. The check
result reports `unknown_model_assets`, their IDs and an "incomplete
companion closure" reason in `ineligible_reasons`, separately from the
pending and hold counts, and the CLI failure names every reason.

Every result is labelled STRUCTURAL ONLY. The tool checks that the evidence
fields are present and consistent; it cannot check that a license says what
the reviewer wrote, so a pass is neither legal clearance nor permission to
publish.

On 2026-11-11 a private draft was generated from the then-current `site_a`
selection report (SHA-256 `62b2ea08...f623`) outside Git, mode 0600, with
SHA-256 `12738f2ae00b18107b4da2ec3e0d71b724a1ddec0602e9df50b1ccebbc301b83`.
It has 273 rows: 163 primary and 110 companion files, 133 companion role
references (13 companions shared by more than one asset), and no path with
both roles. All 273 rows are `pending` with no review, and a repeat draft is
byte-identical. Its `--check` passes structurally and fails eligibility
with 273 pending. The report has 0 unknown models, so the only
ineligibility reason is unreviewed rows. This draft is a worklist, not a rights audit, and no row
in it has been reviewed. Its `pending` values mean the existing `site_a`
evidence has not been migrated into the ledger yet, not that the source
assets were never verified.

## Declared includes

`aa seed --profile ci` and `aa seed-selection` take an opt-in pair,
`--overlap-contract <path> --overlap-peer <peer>`, that adds that peer's
overlap anchors from the contract to the CI selection
(`app/internal/seed/includes.go`):

```sh
aa seed-selection --site <site root> --catalogue seed/profiles \
  --overlap-contract seed/contracts/peer-overlap.v1.json --overlap-peer site_a \
  --out <private report>
aa seed --site <site root> --profile ci \
  --overlap-contract seed/contracts/peer-overlap.v1.json --overlap-peer site_a [--reset]
```

Both flags go together and only with `--profile ci`; neither has a
default, and the peer is never inferred from a directory name. Each
anchor is first held to the same per-peer check as `aa seed-overlap`
(exact asset ID, contract path when given, measured length and SHA-256,
mandatory provenance, exactly one row with those bytes), against the same
`MANIFEST.json` bytes the selection parsed. The anchor rows are then added
after the coverage profile, in manifest order and only once if coverage
already chose one. No coverage-selected post, asset, dimension or file
changes, and no post is added. The seeder and the exporter share this
one selection function.

`aa seed` runs the whole selection offline as a preflight right after
reading its flags, before config, migrations, the bootstrap admin or
`--reset`, so an invalid contract, peer or anchor changes nothing. The
seed then re-runs it and refuses if the contract, manifest or anchors
differ from the preflight. A change after a reset therefore fails the seed
instead of seeding different rows, but the reset has already happened by
then.

With includes, the report schema is `artist-alley.ci-selection/v2`: v1
plus a `declared_includes` block (contract name, schema and SHA-256, peer,
manifest SHA-256, and each anchor's fixture, ID, path, length, SHA-256 and
whether the include added it), and the contract is pinned as the input
`overlap_contract/<name>`. A change to it during an export is refused.
Without the flags the report is v1 and byte-identical to before.
`aa seed-rights` reads both schemas and checks that a v2 block matches its
assets and files, and that `site/MANIFEST.json` and the contract are each
pinned exactly once, present, with the digests the block declares.

## Local package builder

`aa seed-package --site <root> --catalogue <root> --selection <report>
--ledger <ledger> --output <archive.tar.gz>` builds a LOCAL candidate
package (`app/internal/seed/package.go`). It is offline, takes no defaults,
and installs no new archive unless every binding holds:

- the report loads strictly, the ledger binds to it, and
  `CheckRightsLedger` is structurally valid AND eligible. Pending, hold,
  incomplete-review and unknown-model reports fail closed before any site
  byte is read. Manifest licence labels are never read;
- every `site/` and `catalogue/` input pin matches present/absent, size
  and SHA-256 (the v2 overlap-contract pin lives outside both roots and is
  tied to the report by the report loader only);
- every selected asset and post id exists exactly once in the pinned
  `MANIFEST.json` / `posts.json`, each asset's `file_path` equals the
  report's, and every selected post's members are selected assets;
- every closure file is a regular file under the site root reached
  through no symlink, at the reported size.

The archive is a deterministic site-root tar.gz:
- `ci-package.json`: schema `artist-alley.ci-package/v1`, the report and
  ledger digests, the original site pins, the filtered-file digests and the
  per-file digests. It holds no absolute paths and no review evidence.
- the filtered `MANIFEST.json` and `posts.json`: the selected rows in
  source order, each byte-identical to its source row.
- exactly the report's closure files, in path order.

Entries are fixed: regular files only, mode 0644, uid/gid 0, empty owner
names, mtime 0, a fixed gzip header and level, and no directory or link
entries. Each closure file is streamed through SHA-256 into the archive and
refused unless the copied bytes have the reported length and digest, the
file did not grow, and its path still names the file that was read. The
inputs are re-verified after the archive is complete and before it is
installed, and so are the selection report and the rights ledger: both
paths are re-read and must still be regular files with exactly the
SHA-256 of the bytes the eligibility decision used, so a ledger revoked or
a report edited mid-build refuses the install. The output follows the
exporter's rules: outside both roots, mode 0600, temp file plus atomic
rename, and a non-regular or symlinked output is refused. On any refusal
or error no new archive is installed: the temp file is removed and an
archive already at the output path keeps its old bytes.

Structural eligibility is not legal clearance: a package is not release
approval and does not authorize publication. Tests are synthetic only; no
real-data package has been built. Byte identity is measured with this Go
toolchain (gzip/tar output could change with a Go upgrade). Extraction
creates parent directories implicitly.

## Release payload packager (local, not a release)

`seed/scripts/release_dataset.py` (stdlib only, no network, no URLs)
implements the chosen transport locally for a metadata-only dataset root:

- `inspect --root R --site {site_a,site_b}` checks a root read-only.
- `build --root R --site S --output NEW_DIR [--max-part-bytes N]` packages
  ONLY the files `SHA256SUMS` lists under the site's payload prefixes
  (`site_a`: `3d/`, `audio/`, `documents/`, `fonts/`, `images/`, `videos/`;
  `site_b`: `images/`). The payload goes into one deterministic tar.gz
  stream: UTF-8 path order, POSIX pax, fixed member metadata, gzip mtime 0
  and no file name. The stream is written straight into sequential parts,
  each strictly smaller than `N` (default 1,900,000,000; at most 2 GiB),
  without an unsplit archive. `release.json` pins the `SHA256SUMS` hash,
  the metadata files, a digest of the payload list, the counts and bytes,
  the ordered part names, sizes and SHA-256 values, and the whole stream's
  size and SHA-256.
- `verify --root METADATA_ROOT --release DIR --output NEW_ROOT
  [--expect-manifest-sha256 H]` checks the pins and every part before
  extracting. It accepts only listed regular-file members, copies the
  pinned metadata from the metadata-only root, and installs the new site
  root only after the result passes its own `SHA256SUMS`.

Both commands fail closed. They reject unsafe or duplicate paths,
symlinks, unlisted or missing payload files and hash mismatches. They
build in a private temporary sibling, which is removed on any error, and
install with `renameat2(RENAME_NOREPLACE)`, so a pre-existing output is
never replaced. Byte identity holds for one Python and zlib toolchain,
which `release.json` records. Its tests are synthetic only.

Full local candidate archives for both sites were built and verified with
this packager. Each verification reconstructed its site from metadata alone.
The current candidates are retained privately. A 2026-11-12 host crash

has been uploaded or released.
