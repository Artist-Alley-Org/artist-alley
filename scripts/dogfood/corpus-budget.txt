# scripts/dogfood/corpus-budget.txt — the corpus-leak RATCHET (#1245)
#
# The invariant is "a suite run ends with the corpus counts it began
# with". run-ui.sh fails only when a run leaks MORE than this file
# allows, so a new leak is caught from the day it lands.
#
# ⚠️ THIS RATCHET ONLY EVER TURNS DOWN. Raising a number to make a run
# pass converts the guard back into decoration — fix the spec instead.
# The target is all zeroes, and as of #1247 it is met.
#
# ---------------------------------------------------------------------
# WHY THE NUMBERS WENT FROM 60/26/18/30/4 TO ZERO (#1247, 2026-08-23)
# ---------------------------------------------------------------------
#
# Two causes, and they are not the same kind of thing. Both are named
# because "the number went down" is worth nothing without knowing which.
#
# 1. THE INSTRUMENT WAS WRONG, and it accounted for almost all of it.
#
#    The census counted `count(*)`. But `DELETE` is a SOFT delete on
#    assets, posts and collections (`SET deleted_at = NOW()`) and an
#    ARCHIVE on field_definition (`SET status = 'archived'`), and `user`
#    has no delete at all. The row survives every teardown a spec can
#    write, so `count(*)` could never come back down and the target of
#    all zeroes was unreachable by construction. A spec that created
#    three assets and deleted all three still drifted +3.
#
#    So "roughly 25 specs leak" was mostly the census mis-reporting
#    specs that were already correct. Measured on the coding stack the
#    day it was fixed: 151 collection rows, of which 7 were live — the
#    seed catalogue's 7. Every fixture collection ever made had already
#    been cleaned up.
#
#    The census now counts LIVE rows, which is also what the invariant
#    is FOR: the harm #1245 records (the newest-200 window holding no
#    raster image, the bootstrap admin off page 1 of /admin/users) is
#    caused by rows the app can still see, and every index behind those
#    surfaces is partial on `deleted_at IS NULL`. Raw totals are still
#    printed beside the live ones — that is the sweep's backlog, and
#    `aa sweep-fixtures` is what reclaims it.
#
# 2. TWO SPECS GENUINELY LEAKED, and the fixture ledger named them.
#
#    With the census fixed, one table still drifted: assets, +5 a run.
#    The per-spec attribution table (helpers/fixture-ledger.ts) put all
#    five on two specs, both of which upload a real file through the
#    modal and never deleted it — the id is created in the BROWSER and
#    never reaches the test, so there was nothing obvious to delete:
#
#      ui-35-open-vocabulary        3 assets a run
#      vocabulary-extend-cap-789    2 assets a run
#
#    Both now read the id off the modal's own POST and delete it in
#    teardown (helpers/uploaded-rows.ts).
#
# Verified: three consecutive full standalone runs at two workers, each
# ending with the live counts it began with, on a stack carrying the
# accumulated backlog of every earlier run.
#
# Format: <table> <max_tolerated_delta>
assets 0
posts 0
collections 0
