Artist Alley is deliberately boring to operate. **One binary, one
database, one volume.** No microservices, no message bus, no sidecars.

## The shape

- **Single binary.** The Go binary embeds the SvelteKit SPA via
  `go:embed`. Updating the app is a binary (or image) swap.
- **Postgres-only.** No MySQL, no Redis. See
  [ADR 0005](/adr/0005-postgres-only-no-mysql/).
- **Configuration via env.** Everything via environment variables;
  sensible defaults for development.
- **Backup is `pg_dump` + the filestore.** Two things to back up. No
  proprietary export format.

## Install + run

Pick a channel — Docker, Debian/Ubuntu, RPM, static binary, or
Homebrew — and follow the [Install guide](/guides/install/).

For a quick try via Docker:

```bash
docker run -d --name artist-alley \
  -p 8080:8080 \
  -e AA_DB_HOST=postgres \
  -e AA_DB_PASSWORD=secret \
  -e AA_SCRAMBLE_KEY=$(openssl rand -hex 32) \
  -v aa-storage:/var/lib/aa-storage \
  ghcr.io/mscrnt/artist-alley:latest
```

## Release channels

| Channel              | Updated when                      | Use for |
|----------------------|-----------------------------------|---------|
| `:vX.Y.Z`            | exact tag                         | production (pin this) |
| `:vX.Y`, `:vX`       | latest patch on that minor/major  | tolerant production |
| `:latest`            | most recent stable release        | "always shiny" |
| `:edge`              | latest `dev` commit               | preview / pre-merge testing |
| `:edge-{sha}`        | exact `dev` commit                | pinning a specific dev build |

Docker images are signed via Sigstore — see the
[Install guide § Verifying signatures](/guides/install/#verifying-signatures).

## Postgres

Any Postgres 14+ works. Artist Alley creates its schema on first run
via embedded `goose` migrations — there's no separate "migrate
container" or "create database" step beyond the initial role + db.

```sql
CREATE ROLE artist_alley WITH LOGIN PASSWORD 'change-me';
CREATE DATABASE artist_alley OWNER artist_alley;
```

The schema includes a custom `plpgsql` trigger for the full-text
search vectors; no extensions are required beyond what ships with
stock Postgres.

## Storage

Two backends:

- **`fs`** (default) — binary blobs under `AA_STORAGE_FS_ROOT`. Mount
  this as a volume in Docker, or a real disk on bare metal. The Go
  process is the only writer.
- **`s3`** — any S3-compatible API (AWS S3, Cloudflare R2, Backblaze
  B2, MinIO). See the [Install guide § Configuration
  reference](/guides/install/#configuration-reference) for the env
  vars.

Content-addressed: every blob is keyed by its SHA-256. Deduplication
across the whole install is automatic. See
[ADR 0008 — Storage architecture](/adr/0008-storage-architecture/).

## Backup

Two things to back up:

```bash
# Database
pg_dump -Fc -d artist_alley > artist-alley-$(date +%Y%m%d).dump

# Filestore
rsync -a /var/lib/artist-alley/ backup-host:/srv/artist-alley/
```

Restore is the inverse. No proprietary export format, no "backup
mode" toggle — Postgres + a directory.

## Updating

For Docker:

```bash
docker pull ghcr.io/mscrnt/artist-alley:latest
docker stop artist-alley && docker rm artist-alley
docker run -d --name artist-alley ... ghcr.io/mscrnt/artist-alley:latest
```

For systemd:

```bash
# Debian/Ubuntu
sudo apt install ./artist-alley_NEWVERSION_linux_amd64.deb
sudo systemctl restart artist-alley
```

Migrations run automatically on startup. There's no "down" path —
forward-only schema changes only. ADRs (notably 0004) explain the
adjunct-Postgres reasoning.

## Observability

- **Health**: `GET /healthz` (liveness probe — returns 200 when the
  HTTP listener + DB pool are alive)
- **Structured logs**: `AA_LOG_FORMAT=json` for ingestable JSON, or
  `text` for humans. `AA_LOG_LEVEL` controls verbosity.
- **Metrics**: Prometheus-compatible scrape endpoint — see the
  [Monitoring ADR](/adr/) (lands as the metrics phase ships).

## Federation

Artist Alley is built to federate (multi-instance peering with
content sync) — see the in-tree [federation roadmap][federation].
Per-user prefs (theme, language, AI provider override) ride on
`user_profiles` which carries `origin_server_id`. Per-instance
config (auth providers, AI providers, fonts) stays on
`system_config`, which is local to each peer.

For phase 1 you can run a single instance and pretend federation
doesn't exist. The data model already accommodates it.
